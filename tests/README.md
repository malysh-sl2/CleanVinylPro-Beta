# Самоперевірки сервера «Чистий Вініл Pro 2»

Ці файли потрібні лише для розробки: вони не входять у встановлення плагіна і нічого не змінюють
на вашому ПК. Для запуску **не потрібні** ні AI-моделі, ні відеокарта, ні Photoshop.

Перевіряється нова програма (папка `CleanVinylPro2`). Від старої програми (v3.2.1) у папці
`tests/baseline_v321` збережено шість файлів без жодних змін — вони слугують еталоном для порівняння.
Сама стара програма в репозиторії більше не лежить (з версії 4.3.0).

```
python tests/run_checks.py          # швидкий прогін (близько 10 хвилин)
python tests/run_checks.py --full   # більше випадкових кадрів і сценаріїв
python tests/run_checks.py cyc dress  # лише групи, у назві яких є ці слова
```

На Windows із папки, де лежать `CleanVinylPro2` і `tests`:

```
CleanVinylPro2\server\.venv\Scripts\python.exe tests\run_checks.py
```

## Що саме перевіряється

### 1. Те, що не мало змінитися, дає ті самі пікселі, що й стара програма

Порівняння йде в «старому режимі»: повна AI-заливка (колишній режим «Якісний»), захист диму
вимкнено, циклорама 0, одяг вимкнено, «Сліди взуття та розводи» 0, шматки шва оцінюються поодинці,
пил оцінюється за шумом усього кадру, картинки вікна стискаються з якістю 90, студійним обладнанням
вважається кожна довга різка межа, усередині тіней прибираються лише дрібні цятки, пензель і гумка
мають різкий край, а зафарбоване закривається заливкою (`brushSoft` вимкнено). Це місця, де нова
програма навмисно працює інакше (див. частину 2). У великому вікні до цього додається «Розмиття фону» 0:
з розмиттям шар покриває весь фон, і вікно тепер показує це двома відтінками зеленого та
перемальовує мазок пензля (група `mask`); саме розмиття й далі порівнюється зі старою програмою у
групі `process`.

| Група     | Що доводить |
|-----------|-------------|
| `convert` | швидкі перетворення пікселів дають ті самі числа, що й старі формули (перебір усіх значень 8 і 16 біт) |
| `process` | звичайне очищення: новий рушій = рушій v3.2.1, піксель у піксель |
| `session` | велике вікно (відкриття, повзунки, пензель, гумка, «Застосувати»): новий рушій = v3.2.1 |
| `http`    | запити плагіна: новий сервер відповідає так само, як сервер v3.2.1 (потрібен пакет `httpx`) |
| `stage`   | перерахунок у вікні, який бере готові етапи з пам’яті, = повний перерахунок з нуля |
| `quick`   | легкий перегляд після повзунків: шар після «легких оновлень + одного повного розрахунку під час „Застосувати“» = шар за старим способом (повний перерахунок після кожної зміни), піксель у піксель; легке оновлення ніколи не рахує справжній кадр, «Застосувати» рахує його один раз; сам легкий перегляд майже не відрізняється від точного |
| `white`   | помилка «білі плями після Застосувати» не повертається |
| `gpu`     | налаштування cuDNN ніколи не переводить моделі з відеокарти на процесор |

### 2. Те, що нова програма робить інакше

| Група    | Що доводить |
|----------|-------------|
| `cyc`    | циклорама: лінія кута слабшає в кілька разів; людина не змінюється зовсім; кадр без кута не змінюється зовсім; чорний фон: слабкий кут знайдено над краєм плями світла, який учетверо сильніший, і прибрано, а край плями світла не змінюється (версія 4.5.0 брала за кут саме його); на світлому фоні слабка лінія на стіні кутом не стає |
| `dress`  | одяг: зморшки слабшають, а об’єм, колір, фактура, глибока складка, джинс, голова й фон залишаються |
| `speed`  | повна AI-заливка (єдиний режим панелі з 4.7.0), швидка заливка (нею малюється легкий перегляд) і зелене прев’ю позначають одні й ті самі дефекти |
| `smoke`  | навколо людини більше немає «захищеної як дим» смуги; справжній дим захищено, як і раніше. Автоматичний режим (його просить плагін): брудні плями біля ніг, схожі на дим, чистяться; справжня хмара диму захищена; повзунок на 95–100 % захищає без перевірки; вікно каже, що побачило, — з першим скануванням і з кожним оновленням |
| `empty`  | на порожньому кадрі людина не «вигадується»; справжня людина окреслюється так само, як раніше |
| `format` | формат 5:7: розмір, стик без шва, зерно, 8 і 16 біт, вертикальний і горизонтальний кадр, людина біля краю |
| `stains` | «Сліди взуття та розводи»: плями на підлозі вирівнюються біля людини так само, як подалі від неї (стара програма біля людей не робила нічого); тінь під ногами, м’яка тінь збоку, червоний м’яч, жовтий скотч, світло й сама людина лишаються; кадр без плям не змінюється; повзунок дозує силу; на темному фоні край світлової плями від лампи не стає різкішим; 8 і 16 біт |
| `seam`   | шов вінілу: два короткі шматки однієї лінії по обидва боки від людини прибираються разом (поодинці жоден не досить довгий); дві різні лінії не з’єднуються; один короткий шматок не чіпається; ледь помітний і дуже темний шов прибираються однаково — з циклорамою і без неї; разом із лінією кута: кут знайдено там, де він є, шов прибрано з обох боків; тонкий і ледь помітний шов не сприймається за кут; лінія кута з вимкненою циклорамою перемальовується або вся, або ніяк (шматками — ніколи); дві короткі лінії на одній висоті, між якими видно підлогу без лінії, швом не вважаються (за широкою сукнею ті самі шматки — шов); тонка лінія вздовж межі світла (підлога з одного боку світліша на 10 рівнів і більше) швом не вважається, а шов на підлозі, яка з одного боку ледь світліша, прибирається; самі правила перевірено на намальованих масивах: скільки підлоги видно між шматками, вигнутий шов уздовж власного ходу, профіль шва, повільного переходу світла й межі світла |
| `mask`   | коли вирівнюється весь фон: «Маска» відрізняє знайдене й перемальоване (яскраво-зелене) від просто вирівняного (блідо-зелене); `mask_share` рахує перше, `layer_share` — увесь шар; мазок пензля по вирівняному фону перемальовується під час «Застосувати»; стерте гумкою не змінюється зовсім; «залити» показує шар на всьому кадрі й не додає нічого до «знайденого»; очистити / інверсія / скидання; легке оновлення й повний перерахунок дають ті самі числа; другий прохід теж позначається |
| `brush`  | пензель і гумка великого вікна (з 4.7.0): край м’якого мазка плавний (перехід за 65 пікселів проти 13 у жорсткого, найбільший стрибок 1,6 % проти 7 %), у гумки так само; світла пляма з цятками під мазком зникає, тон продовжується з фону навколо (похибка менш ніж 1 рівень), зерно лишається таким, як поруч; вікно показує те саме, що шар; м’який пензель не змінює в людині жодного пікселя, жорсткий перемальовує; мазок уздовж краю тіні не розмазує край; тінь, якої мазок лише торкнувся, не затемнює стіну, а пляма поруч вирівнюється; майже весь фон, замальований пензлем, зберігає тон; «залити» не перемальовує нічого й скасовується кроком назад; 16 біт; край мазка, названий у запиті панелі, доходить до рушія |
| `scene`  | автоматичний пресет: кадр розпізнається правильно (повний зріст / по пояс / ближній план / темний фон; вертикальний і горизонтальний кадр, одна-дві людини, сукня або штани, стійка біля краю, порожній кадр); вікно, відкрите з автоматичним пресетом, збігається з вікном, де цей пресет вибрано вручну, — разом із шаром після «Застосувати»; темний фон бере свій набір для кожного плану, без нього — загальний темний, далі набір плану, далі стандартний; світлий кадр темного набору не бере ніколи; фони власника: чорний (13–20) і темно-сірий (31) — темні, сірий (52) і світло-сірий (78) — ні |
| `dark`   | темний фон з освітленою підлогою: звичайний шум освітленої частини не береться за пил (на штучному кадрі за пил бралося 64 % освітленої підлоги, тепер 0,4 %), а справжні цятки знаходяться всі; на рівно освітленому кадрі маска пилу та сама, що й раніше; саме правило перевірено на намальованих картах шуму. Картинки великого вікна для темного кадру зберігають дрібний шум (JPEG 100), для світлого лишаються на 90; оновлення й мазок цього не псують |
| `gear`   | студійне обладнання визначається за «тілом»: пил біля різкого краю тіні знаходиться (14 цяток із 14, за старим правилом 5), подряпина на підлозі прибирається — раніше обидва місця лишалися недоторканими як «обладнання»; стійка, кабель і відбивач біля краю кадру не чіпаються; сама тінь не змінюється; край тіні не вважається димом; зелене прев’ю показує те саме |
| `shadow` | брудна пляма всередині тіні прибирається (раніше всередині тіні прибиралися лише дрібні цятки); край тіні, її щільніші місця, тінь під взуттям, вузький «язик» тіні й світла пляма в тіні не чіпаються; саме правило перевірено на 15 намальованих плямах із числами з кадрів власника (його пляма під тінню руки береться, слабкі плями вздовж краю плями світла й шматок різкого краю тіні — ні) |
| `undo`   | велике вікно: шість видів правок маски (мазок гумки, мазок пензля, залити, очистити, інверсія, мазок по інвертованій масці) скасовуються й повертаються точно — маска, перегляд і картинки збігаються з тим, що було; нова правка після кроку назад стирає «кроки вперед»; зберігається 40 кроків; після зміни повзунків (легке оновлення й повний перерахунок) крок назад дає вікно, яке збігається з вікном без цієї правки, і той самий шар після «Застосувати»; те саме через запити плагіна |

### 3. Програма навколо рушія

| Група    | Що доводить |
|----------|-------------|
| `server` | перенесення налаштувань, розбір пакетів, одна версія всюди; порт, назви, ідентифікатори плагіна, завдання Windows і папка налаштувань не збігаються зі старою програмою |
| `http`   | (крім порівняння зі старим сервером) бекап налаштувань: файл містить рівно те, що надіслала панель; два бекапи за одну секунду не затирають один одного; у списку лише справжні бекапи цієї програми (перейменований файл теж; файл іншої програми з такою самою будовою — ні); прочитати можна тільки файл із папки бекапів; із копій «перед відновленням» лишається 10 останніх, бекапи власника не видаляються ніколи; папка, у яку не можна писати, дає зрозумілу помилку |
| `plugin` | налаштування у самому плагіні; поведінка великого вікна (див. нижче); актуальність файлу `CleanVinylPro2.ccx` й архіву для завантаження `CleanVinylPro2.zip`; закінчення рядків CRLF у файлах `.bat`. Потрібен Node.js |

### 4. Встановлення: спільні папки, Python, бібліотеки (`tests/install_checks.py`)

| Група     | Що доводить |
|-----------|-------------|
| `folders` | файл `folders.ini` однаково читають Python і `install_windows.bat`; у ньому саме ті папки, які назвав власник; моделі знаходяться у спільній папці (і в папці всередині неї); обірване завантаження не вважається моделлю; якщо файлу бракує — спочатку він копіюється з іншої копії програми на цьому ПК і лише потім завантажується; перед завантаженням 1,2 ГБ інсталятор питає |
| `install` | `server/setup_env.py` справді запускається так, як його запускає `install_windows.bat`, в імітації комп’ютера (спільна папка, дві копії програми, стара програма поруч). Перевіряється: бібліотеки ставляться один раз у спільну папку, а в папці програми їх немає; повторний запуск і друга копія програми обходяться без pip; після «перенесення» Python середовища перев’язуються без перевстановлення; бібліотеки й модель беруться зі старої програми без інтернету, і стара програма при цьому не змінюється; папка з власними бібліотеками переходить на спільні; перерване встановлення робиться заново; порожні рядки `folders.ini` дають стару схему «все в папці програми» |
| `bat`     | файли `.bat` тут запустити неможливо (немає Windows), тому вони читаються так, як їх читає `cmd.exe`: дужки блоків, мітки, тексти `echo`, які Windows сприйняла б за команду, змінні, маленькі програми Python усередині. Сам «читач» перевіряється на 11 навмисних помилках і на двох справжніх помилках інсталятора v3.2.1 |

Щоб перевірка `install` не потребувала інтернету, справжній `pip` ставить маленькі пакети-замінники
з місцевої папки. Чого ця імітація **не** бачить: справжній `cmd.exe`, справжні середовища Python
на Windows (там `python.exe` середовища — окремий запускач), права доступу Windows, справжні
бібліотеки з CUDA.

### 5. Коли панель звертається до сервера (велике вікно)

`tests/plugin_preview.test.js` запускає **справжні** `index.html` і `main.js` панелі в імітації
браузера: Photoshop і сервер замінено простими заглушками, а мишка «тягне» повзунки й «натискає»
кнопки. Перевіряється:

* поки повзунок тягнуть — до сервера не йде жодного запиту на перерахунок;
* після відпускання — одне легке оновлення перегляду (без вікна прогресу, налаштування не
  закриваються); кілька змін поспіль дають одне оновлення; нове перетягування відкладає оновлення;
* повзунки «Сила» й «Одяг» перерахунку не запускають;
* кнопка «Точний перегляд» робить повний перерахунок;
* один режим (4.7.0): кнопки швидкості у вікні немає; кожен запит просить повну AI-заливку — також
  коли налаштування чи пресет, збережені старішою версією, кажуть «швидкий»;
* край пензля й гумки (4.7.0): спочатку м’який; нижня кнопка вмикає жорсткий, верхня повертає
  м’який; вибір іде до сервера з кожним мазком, записується в налаштування й у бекап і
  повертається після перезапуску Photoshop; слід мазка під курсором блідий у м’якого й щільний у
  жорсткого;
* з 2× проходом і зі старою версією сервера повзунки самі нічого не запускають;
* «Застосувати» передає серверу значення, які стоять на повзунках, і не губить своє вікно прогресу;
* після помилки оновлення не повторюється без кінця; закриття вікна скасовує оновлення, що чекало;
* вікно відкривається з чистим фото; «До / Після» перемикає оригінал і чисте фото, «Маска» —
  маску і чисте фото; мазок пензлем чи гумкою сам вмикає маску;
* клік по пресету дає один запит саме з його значеннями і напис про те, що змінилося; пресет, який
  вимикає фракції, гасить AUTO, наступний пресет вмикає AUTO назад;
* автоматичний пресет: набори значень їдуть разом із фото, вибір сервера з’являється на повзунках
  без жодного додаткового запиту; повзунок, зрушений під час сканування, має перевагу; вилучений
  пресет не пропонується; з вимкненою галочкою «Авто» нічого не надсилається;
* кнопка, натиснута, поки сервер запускається, спрацьовує сама, щойно він відповість; сервер при
  цьому запускається один раз; повторне натискання скасовує очікування; якщо документ змінився —
  нічого не запускається; сервер, який так і не стартував, закінчується зрозумілою помилкою;
* сервер іншої версії, що лишився працювати після оновлення: панель каже, як його перезапустити;
* дим: захист вимкнений, доки його не ввімкнуть (галочка, перемикач або пресет «Зйомка з димом») —
  також коли у файлі налаштувань немає значень повзунків (файл обрізали вручну);
  кожен запит просить «захищати дим лише там, де він є»; галочка, перемикач і повзунок диму
  дають напис про те, що побачив сервер (на кадрі без диму — що перегляд оновлено, але нічого не
  змінилося), і той самий текст лишається в рядку підказки; якщо захист вимкнено, а в кадрі видно
  дим, вікно попереджає про це одразу; напис зникає після іншої зміни; старий сервер, який про
  дим мовчить, нічого не ламає;
* зміна стандартних значень доходить до ПК, де пресети вже збережено: «Циклорама» 65 % (4.4.0),
  вимкнений захист диму, «Пил» 80 і «Циклорама» 65 у «Темному ключі» (4.5.0) — один раз, не
  чіпаючи власних пресетів і значень, які власник змінив сам; три нові темні пресети стають у
  список одразу під «Темним ключем»;
* темний фон: автоматика ставить темний пресет свого плану; вилучений пресет замінюється загальним
  темним, далі пресетом плану, далі «Студією»; старий сервер дає «Темний ключ»;
* крок назад: Ctrl + Z, Ctrl + Shift + Z, Ctrl + Y (також в українській розкладці) і дві кнопки;
  у полі для тексту клавіші лишаються за полем; правки йдуть до сервера по черзі, тож запізніла
  відповідь не накриває новішу картинку; нове вікно починає без кроків; старий сервер — підказка
  про перезапуск;
* «Скинути пресет»: перше натискання лише питає, друге повертає вибраному стандартному пресету
  його значення — тільки йому; значення йдуть на повзунки, у перегляд, у файли на ПК і на сервер;
  одне натискання забувається за кілька секунд; для власного пресета нічого не змінюється;
* бекап: файл містить усі пресети й налаштування; відновлення — після другого клацання, з копією
  того, що було; після відновлення пресети, перемикачі й повзунки точно такі, як збережено;
  бекап старішої версії отримує змінені стандартні значення й нові пресети; старий сервер,
  помилка запису, порожня папка й зіпсований файл дають зрозумілі повідомлення.

```
npm install --prefix tests jsdom      # один раз; пакет потрібен лише для цього тесту
node tests/plugin_preview.test.js     # близько 3 хвилин
```

Без пакета `jsdom` тест пише `SKIPPED` і нічого не перевіряє.

## Навмисні дефекти (`tests/try_defects.py`)

Перевірка, яка пропускає дефект, — це діра в перевірках. Тому для нових правил є список навмисних
дефектів: скрипт по одному вносить їх у програму (точна заміна шматка тексту), запускає групу
перевірок, до якої дефект належить, повертає файл і пише «caught» або «NOT CAUGHT».

```
python tests/try_defects.py           # усі дефекти зі списку (близько 11 хвилин)
python tests/try_defects.py brush     # лише ті, у назві чи групі яких є це слово
python tests/try_defects.py panel:    # лише дефекти панелі (близько хвилини)
python tests/try_defects.py --list    # показати список, нічого не змінюючи
```

Зараз у списку 29 дефектів версії 4.7.0: 18 у рушії та сервері (пензель, гумка, «залити») і 11 у
панелі (дві кнопки краю пензля, один режим).

Дефект панелі вноситься не в саму програму, а в копію папки плагіна: на цю копію вказує змінна
`CV_PLUGIN_DIR`, і на ній запускаються тест налаштувань та потрібні сценарії тесту великого вікна.
Спійманим він вважається лише тоді, коли на такій самій копії без дефекту ці тести проходять.
Потрібні Node.js і пакет `jsdom`.

Поки скрипт працює, не редагуйте файли програми, не збирайте пакет і не запускайте перевірки самі:
дефекти рушія та сервера він вносить у файли на місці й повертає їх наприкінці (також після
Ctrl+C). Список стосується того, що було новим в останній версії; коли код зміниться і запис
перестане підходити, скрипт скаже «out of date» і нічого не змінить.

## Як це працює

* Дві нейромережі замінено простими детермінованими замінниками (`harness.py`), а замість фото
  малюються штучні кадри: стіна, підлога з кутом, «людина», тінь, шов вінілу, пил, волоски; для
  одягу — «сукня» зі зморшками, глибокою складкою і «джинсами». Увесь інший код працює так
  само, як у Photoshop.
* Стара версія (v3.2.1) береться з папки `tests/baseline_v321` (файли `engine.py` і `server.py` без
  змін) і запускається поруч із новою на тих самих кадрах. Якщо цієї папки немає, порівняння зі
  старою версією пропускаються, а група `server` повідомляє про помилку.
* Чого ці перевірки **не** бачать: роботу в самому Photoshop, справжні AI-моделі, відеокарту і
  запуск файлів `.bat` у Windows (вони лише «прочитані», див. групу `bat`). Це можна перевірити
  лише на комп’ютері з Photoshop.

Після будь-якої зміни файлів плагіна (`CleanVinylPro2/uxp-plugin`) перезберіть пакет, а після
будь-якої зміни в папці `CleanVinylPro2` — архів для завантаження:

```
python tools/build_ccx.py
python tools/build_zip.py
```

`build_zip.py` заодно повертає закінчення рядків CRLF у файлах `.bat`, у `folders.ini` та в інструкції, якщо якийсь
інструмент перетворив їх на LF (з такими `.bat` Windows може працювати неправильно).

## Сторінка для завантаження архіву

```
python tools/serve_download.py            # сторінка з однією кнопкою «Завантажити ZIP», порт 18746
python tools/serve_download.py --check    # самоперевірка: сторінка й архів віддаються правильно
```

Потрібна там, де файли лежать не на вашому ПК, а у віддаленому робочому просторі: у вікні перегляду з’являється
сторінка з назвою програми, версією та кнопкою, яка завантажує `CleanVinylPro2.zip`. Архів щоразу читається з
диска, тож після `build_zip.py` сторінку перезапускати не треба. До самої програми сторінка не належить і в
архів не потрапляє. Порт 18746 — той самий, що в сервера програми, тому в одному робочому просторі запускайте
щось одне.
